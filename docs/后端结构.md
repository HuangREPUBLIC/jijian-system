# 后端代码怎么找、怎么改

后端是 Express + MySQL，入口 `server/index.js`，所有接口都挂在 `/api` 下。

## 想改某个接口，打开哪个文件

接口按业务分在 `server/routes/` 下，路径和权限（`A.authRequired` / `A.managerRequired`）都写在每个接口的定义那一行：

| 想改 | 文件 | 里面的接口 |
|---|---|---|
| 登录、当前用户、改密码、员工增删改、岗位列表、操作日志 | `routes/users.js` | `/login` `/me` `/password/change` `/users` `/roles` `/operations` |
| 工序、工序模板、每日工资 | `routes/processes.js` | `/processes` `/process-templates` `/settings/daily-wage` |
| 款式、缩略图、图片上传、尺码颜色客户选项、款式工序（含同步到裁床单） | `routes/styles.js` | `/styles` `/style-options` `/upload` `/styles/:id/processes` |
| 打点（扫菲票记录）、全员打点流水 | `routes/scan.js` | `/scan` `/scan-all` |
| 考勤、效率、工资 | `routes/wages.js` | `/attendance` `/efficiency/*` `/payroll/*` |
| 应用内通知、系统推送订阅 | `routes/notifications.js` | `/notifications*` `/push/*` |
| 裁床单、菲票（扎）、生产进度、打印数据 | `routes_cutting.js` | `/cut-orders*` `/bundles*` `/production/*` |

`routes/index.js` 只负责把上面这些挂到一起，不含业务逻辑。

## 其他文件

| 文件 | 干什么 |
|---|---|
| `routes/shared.js` | 多个路由文件共用的小函数（改动描述、岗位名等） |
| `db.js` | MySQL 连接、建表语句（`DDL`）、种子管理员、启动初始化 |
| `auth.js` | 登录态校验：`authRequired`、`managerRequired` |
| `cutting.js` | 裁床的纯计算：按件数矩阵生成扎号（不碰数据库，有单元测试） |
| `pricing.js` | 工序单价解析（默认价 / 按尺码定价） |
| `notify.js` `push.js` | 站内通知写入、系统推送发送 |
| `oplog.js` | 操作日志 |
| `async_router.js` | 让 async 接口抛出的错误交给错误中间件，不会让请求挂住 |

## 几个约定

- 一个业务文件里，如果某个辅助函数只有这个业务用，就放在该文件里靠近用它的接口；被两个以上业务文件用，才放进 `routes/shared.js`。
- 考勤、效率、工资放在同一个文件，因为它们共用同一套工时口径（`EFF_HOURS_EXPR`、`effectiveHours` 等），拆开会互相引用。
- 改完接口跑 `npm test`。测试覆盖建表迁移、扎号计算、单价解析、登录与员工管理、裁床打印及其权限；款式、打点、考勤、工资这些接口目前没有专门的测试，改动后要自己在页面上点一遍。
